## 1. 定位

战略框架采用第一个 AI 的判断（正确）：把项目从"LLM 生成知识库"改造成"PDF-grounded claim database + LLM synthesis"。LLM 可以综合，但每个定量 claim 必须来自原文；生成方不得自报 verified，verified 只能由核查流程产生。先把 5 个金标准原型做成可信闭环，再批量扩展，不要先扩到 100。

本方案在此框架上，修正了几处事实误判，并补充了验证瓶颈、机制建模、分支治理三个被低估的点。

## 3. 战略框架（PDF-grounded claim database）

一个能支撑 ADRMATS 的库，每个原型最低要能回答 6 个问题，且每个结论可追到真实 PDF/DOI/页码：① 解决什么自然问题；② 靠什么机制（官能团/结构/过程/系统）；③ 机制如何映射到可制备材料特征；④ 在什么水质条件下有效或失效；⑤ 对哪些污染物有实验证据（qmax/去除率/动力学/循环）；⑥ 每条结论能否追到原文。

当前文件系统架构、feature-mapping、taxonomy、prototypes_db 结构都合理。不合格的是内容层：848 条数据全未核实，且部分串库。这不是格式问题，是证据污染。直接接入会让下游设计器按错误数值排序候选材料，污染 Proposer/Critic/解释 Agent 的共同上下文。

成功标准从"条目数量"改成"可核查 claim 数量"。

## 4. 项目最高准则（quality-first · 一切修改服从）

1. 质量高于进度与数量。宁可 5 个真原型，不要 36 个掺假的。
2. 每条数值必须可溯源到一篇真实文献的具体位置（DOI 或专利号或标准号 + 页/表/原文句）。溯源不到的，不进库。
3. 一个原型 = 一个仿生身份。不混入其他生物的叙事和机制（同类多物种除外）。
4. 未经独立核查的数据标 unverified，ADRMATS 不得当事实用。
5. 空白优于错配。没把握就留空，绝不编造、绝不张冠李戴。
6. 有引用不等于可信。综述里别的材料的 qmax 不得归给本原型，除非追到原始实验论文。
7. 拿不准就停下问人（见第 10 节）。任何"为凑达标想放宽核查或保留可疑数据"的念头出现时，立即停。

## 6. 优先级任务（P0 → P1 → P2，前序未过验收不做下一张）

### P0-1 清理 6 个 chimera（组织字段 + 机制串库）
- **范围**：shark-skin、polydopamine-coating、spider-silk、water-strider-leg、cactus-spine、superhydrophobic-artificial。
- **改法**：对每个原型，只保留 `routing.prototype_targets` 确实指向它、且 `biomimetic_metadata.organism_scientific` 与原型一致的论文的数据；其余删除。organism 字段改回单一物种（superhydrophobic-artificial 若确为多源超疏水合成体，可保留多源但需在 features 注明，不得混入鲨鱼/壁虎这类无关项的性能数据）。叙事和机制只能来自主题为该原型的论文，绝不 `dict.update()` 跨生物合并。
- **验收**：6 个原型 organism 单一（或同类合理多源），机制与叙事主题与原型 ID 一致；新建的 `tools/check_chimera.py` 通过。

### P0-2 机制建模重构（根治 lotus 膨胀 + functional_groups 缺失 + mussel 污染）
- **问题根因**：抽取没区分"机制(原理)"与"实例(某材料的性能)"。lotus 的 358 条、mussel 的污染、97% 缺 functional_groups 都源于此。
- **改法**：在 schema 里把二者分开。`mechanisms[]` 只放原理级条目，每条必须有 `name`(原理)、`description`、`functional_groups`、`source`/`ref_doi`；按材料/论文的性能条目移入 `performance_data[]`。重新聚合时按此归类，机制去重（同一原理合并），把误归入机制的性能条目移走。functional_groups 能从原文读到的填，读不到的留空、不编造。
- **验收**：lotus 机制条目降到合理数量（原理级，通常个位到十几条）；机制条目 functional_groups 覆盖率显著上升（能从文献读到的都填上）；机制里不再混入"某材料接触角/某织物性能"这类实例条目。

### P0-3 verification 核查层（最关键，决定 ADRMATS 可用度）
- **改法**：实现核查流程。对每条 `source=literature` 的性能数据：① 解析 ref_doi（Crossref/web），确认文献存在；② 打开对应 PDF/source_file，确认该数值确实出现在指定页/表，且材料与污染物一致；③ 三步全过 → `verification=verified`，任一步失败 → `needs_review` 或删除。产出核查报告（真实/编造/无法核实 表）。
- **综述特例**：综述里的表格数据不得直接归给原型，除非追到原始实验论文并以原始论文为 source。追不到的标 needs_review。
- **范围与顺序**：先做第 7 节的 5 个金标准原型，全部数据 100% 核查。其余原型的全量核查见第 8 节（信任模型）。
- **验收**：5 个金标准的性能数据全部 verified 或被降级/删除；不存在"verified 但 ref_doi 解析不到 / 无 source_file"的条目。

### P0-4 校验脚本（硬门槛，每次改动后跑）
- **改法**：新建/补齐 `tools/validate_consistency.py`：① 断链（feature-mapping 每个 ID 有非空原型）；② 孤儿目录；③ feature-mapping 与 prototype_routing ID 集一致；④ frontmatter 必填字段；⑤ performance_data 中 literature/patent/standard 必须有 ref_doi 或 source_file，llm_inference 必须无 ref；⑥ verified 条目必须有可解析 DOI 或 source_file（禁止自称已核实）；⑦ 单一物种一致性（organism 与 ID 领域不符报错）；⑧ 重复条目（同 pollutant+material+value）。
- **验收**：脚本能拦住上述全部违规并返回非零；接 pre-commit。

### P1-1 补 pollutant 字段（245 条）
- **改法**：对 245 条缺 pollutant 的性能数据，回原 PDF/JSON 提取污染物；提不到的标 needs_review、不进 Layer 2 匹配。
- **验收**：缺 pollutant 的比例显著下降；剩余的明确标记不可匹配。

### P1-2 pollutant_prototype_map 只核对、不重建
- **改法**：核对 map 覆盖（当前 22/22 有数据原型已在内）。仅补真正遗漏的；权重沿用已导出的，不要推倒重建（多个 AI 在这点误判了，别照做）。
- **验收**：每个有数据原型在 map 中；无指向空原型的高权重。

### P1-3 空原型保持低覆盖
- **改法**：无性能数据的原型保持 `coverage=low` + `status=needs_literature`，不硬填。（当前已无"active 却空"，保持即可。）
- **验收**：无 active 却 0 数据的原型。

### P2-1 functional_groups 批量补全（1329 条，量大）
- **改法**：在 P0-2 重构后，对仍缺 functional_groups 的机制条目，优先从原文补；确实无法从文献定位的，可由 LLM 推断但标 `source=llm_inference`、不得挂文献引用、不得标 verified。
- **验收**：functional_groups 覆盖率上升；推断项明确标 llm_inference。

### P2-2 MOF JSON 拆分 + 污染物名归一
- **改法**：metal-organic-framework.json（259KB）按需拆分（如按污染物类别分文件），不影响 schema。污染物名归一（如 "Methylene Blue"/"MB"/"亚甲基蓝" 统一），消除同物异名导致的 Layer 2 漏匹配。
- **验收**：单文件不过大；同一污染物在库内唯一命名。

## 8. 验证瓶颈与信任模型（必须正视，不要无限拖延）

848 条数据全量逐条开 PDF 核对是大工程，扩到 100 个原型会到几千条。每一轮都把核查往后拖（现在仍 0/848），库就永远不可信。必须二选一并明确写进计划：

- 要么把全量核查作为一个真实、排期的阶段：金标准先做，其余按 feature-mapping 引用频次逐个核查。
- 要么采用并明确记录一个分级信任模型：按来源质量（原始实验论文 > 综述）+ 多来源相互印证 + 人工抽审，给 confidence 分级；高频被检索的原型优先做到 verified，其余明确标 unverified 供下游知情。

无论哪种，全量核查完成前，未核实数据必须显式带 unverified 标志，让 ADRMATS 知道哪些能当事实、哪些只能当线索。把方案定下来比再做任何结构性工作都重要。

## 9. 数据判定规则（机械套用，不靠判断）

- 可标 `verified` ⟺ source∈{literature,patent,standard} 且 ref 可解析 且 数值在该来源指定页/表确实出现、材料与污染物一致。三者缺一不可。
- 必须删除 ⟺ 来源查无此文，或数值在来源中找不到。
- 标 `needs_review` ⟺ 有来源但缺页码/引用过短/精度不一致/无号/来自综述未追到原始论文。
- 判为 chimera（需清理）⟺ organism 含 ≥2 个不同类生物 且 机制/叙事主题与原型 ID 领域不符（同类多物种、或确为多源合成类除外）。
- 缺来源 ⟹ 留空，不编造。
- 综述数据 ⟹ 只作线索，不直接归属，除非追到原始实验论文。

## 10. 何时必须停下来问人

- 某原型清洗后内容过少，不确定标低覆盖还是补文献。
- 某条数值在来源里找不到，但删了会让原型不达标 → 一律删/降级，绝不为达标保留；若为难，问。
- 信任模型二选一拿不准（第 8 节）。
- 出现"为让原型达标想放宽核查标准"的念头 → 立即停，问。
