### 问题一：当前提取使用 v1 提示词，缺少 v2 新增字段（P2，非缺陷）

4 篇最新 JSON 的 schema_version 全部是 `biomimetic-v1`。v2 新增了三个字段：

- `routing.prototype_targets`（33 个标准原型 ID 映射 + 置信度）
- `biomimetic_metadata`（organism_scientific、biomimetic_dimension、features、applicability、engineering_constraints）
- `biomimetic_narrative`（problem_definition、biological_solution、key_features、design_mapping、explainability_anchors）

**v1 本身没有缺陷。** v1 的核心产出（knowledge_items 粒度、provenance 覆盖率、evidence 页码）质量扎实。v2 新增字段是仿生设计库下游消费时需要的，不是提取质量的问题。

**v2 是怎么来的：** 用户要求为专利和标准写专项提取策略，AI 在同一个文件中一并加入了仿生设计库字段和 evidence 质量分级规则。v2 实际是两件事的合并：(1) 专利/标准专项策略（用户要求的）；(2) 仿生字段升级（AI 顺带加的，来自质量诊断中发现的桥接缺口）。

**大部分 v2 字段可以不通过重跑获得：**

| v2 字段 | 能否从 v1 数据推导 | 推导方式 |
|---------|-------------------|---------|
| prototype_targets | 能 | standardize_organism.py 的 ORGANISM_TO_PROTOTYPE 映射表（175 条）+ v1 的 biomimetic_organism 字段 |
| biomimetic_metadata.applicability | 能 | v1 的 knowledge_items 中 context 字段已包含 pH/温度等实验条件 |
| biomimetic_metadata.features | 部分能 | 从 knowledge_items 的 domain_direction 和 parameter 推导 |
| evidence 质量分级 | 能 | relabel_evidence_quality.py 后处理脚本 |
| biomimetic_narrative（5 个叙事子节） | **不能** | 需要 LLM 从 PDF 原文综合，无法纯脚本推导 |

**建议**：论文不需要用 v2 重跑。在桥接管道阶段用脚本补 prototype_targets 和 metadata，仅对标标杆原型相关的论文用 LLM 生成 biomimetic_narrative。v2 提示词用于任务 2（专利重跑）和任务 3（标准重跑）。

如需切换，改为 `biomimetic_extraction_prompt_v2.md` 即可。

### 附录：GitHub 推送失败根因分析

**现象**：Claude Code 推送 `feature/extraction-results-clean` 分支到 GitHub，3 次均失败，每次都把 300+ 篇 PDF（1.7GB）一起推。

**根因**：不是 `.gitignore` 的问题。commit `9ee5da0`（"feat: 论文提参质量优化完成"）将 343 个 PDF 文件提交进了 git 对象数据库。后续的 `.gitignore` 修改只能阻止新文件入库，无法清除已进入对象库的 PDF blob。加上两个 stash 引用着这些对象，导致无法被垃圾回收。

**诊断证据**：
- `git count-objects -vH`：723 个松散对象，**1.39 GiB**
- `git stash list`：2 个 stash（分别引用含 PDF 的 commit）
- `git show 9ee5da0 --stat`：675 files changed, 949973 insertions（含 343 个 PDF）
- GitHub 上 `feature/extraction-results-clean` 返回 404（从未推送成功）
- `feature/extraction-results-clean` 本地分支已被删除，但 commit `1d9a3f4` 仍可通过 reflog 恢复

**为什么反复修 .gitignore 没用**：`.gitignore` 只控制 `git add` 时哪些文件被忽略。PDF 已经在 commit `9ee5da0` 中成了 git 对象，即使后续 commit 删除它们，对象仍然存在于 `.git` 目录中。推送时 git 需要传输所有远端没有的对象（包括历史中的 PDF），所以一直卡住。

**修复命令**（可直接交给 Claude Code 执行）：

```bash
# 1. 删除 stash，解除对 PDF 对象的引用
git stash drop stash@{0}
git stash drop stash@{0}   # 删完第一个后，原来的 stash@{1} 变成 stash@{0}

# 2. 清除 reflog 并垃圾回收，移除不可达的大对象
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 3. 验证清理结果（应从 1.39GB 降到几 MB）
git count-objects -vH

# 4. 从已有的 clean commit 恢复分支（该 commit 有正确的 .gitignore）
git branch feature/extraction-results-clean 1d9a3f4

# 5. 推送
git push origin feature/extraction-results-clean
```
