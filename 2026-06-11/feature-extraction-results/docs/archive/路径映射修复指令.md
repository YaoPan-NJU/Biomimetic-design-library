### 修复方案（三选一，按优先级）

**方案 A（最优）：找回原始 PDF**

如果 PDF 是从某个网盘、数据库或课题组共享目录下载的，重新下载到 `仿生文献库/论文/` 的对应子目录（第1组-配位螯合、全局综述），然后重跑：
```bash
python3 tools/verify_data.py --db-dir prototypes_db
```

**方案 B（次优）：用 LitExtract 的 raw output 替代 PDF 核查**

LitExtract 提取时保存了 raw output（OpenClaw 的完整对话记录），里面包含 LLM 从 PDF 读到的原文引用。可以用这些 raw output 作为核查依据：

1. 在 `/tmp/openclaw/litextract_runs/` 下找到对应论文的 raw output
2. 从 raw output 中提取原文引用文本
3. 与 `prototypes_db/*.json` 中的 performance_data 交叉比对

**方案 C（保底）：标记为 needs_review 并记录原因**

如果 PDF 无法找回，在每条 needs_review 的 item 中加上 `review_note` 字段说明原因，不要假装核查过了：

```python
for item in performance_data:
    if item['verification'] == 'needs_review':
        item['review_note'] = 'PDF 源文件丢失（第1组-配位螯合/全局综述目录不存在），无法执行 PDF 核查。数据来自 LitExtract 提取 JSON，有 DOI 和页码锚点，但未独立核实。'
```
