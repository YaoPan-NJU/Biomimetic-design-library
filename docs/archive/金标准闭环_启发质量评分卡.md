# 金标准闭环 · 启发质量评分卡（v1.1）

> 适用项目：Biomimetic-design-library（ADRMATS 的仿生**启发**检索模块）
> 用途：验证最小链路「污染物输入 → 原型匹配 → 设计思路输出 → 对抗设计模块接手」的**启发质量**
> 配合阅读：《分层核查标准_交本地AI执行》
> 编制日期：2026-06-08

---

## 0. 评分原则（先读，决定打分尺度）

本评分卡评的是**启发质量**，不是**数值准确性**。库的职责是"匹配出对题、不跑偏、不串库的设计思路",真正的方案准确性归下游对抗设计模块。对新污染物，不能用污染物名称硬查来替代匹配质量；必须看污染物画像、分子特征到机制的连接是否说得清。因此：

- **不**因为某条 qmax 未 verified 就扣分；只要它被诚实标了等级、且未被当事实断言，就不影响启发质量。
- **重扣**串库、跑偏、把推断当事实、泛泛套话——这些直接破坏库的核心功能。
- 满分不等于"方案可执行",满分等于"给了下游一个可靠、对题、可溯源、标注诚实的起点"。

打分用 1–5 Likert。每个维度给 1/3/5 锚点，2/4 取中间态。

---

## 1. 八维评分（每维 1–5）

### D1 匹配相关性（Relevance）
匹配出的原型是否真的对应目标污染物 / 水质 / 工程约束。
- **5**：top 原型全部领域对题；直接证据或分子特征画像都能清楚解释为什么这些机制适用于该污染物去除场景。
- **3**：top 原型多数对题，混入 1–2 个边缘或勉强相关项。
- **1**：返回原型与目标场景基本无关，或只靠污染物名称/大模型猜测硬凑，缺少分子特征到机制的连接。

### D2 覆盖度 / 多样性（Coverage & Diversity）
是否给出有用的多种生物策略，而非单一显然项或冗余重复。
- **5**：覆盖 ≥2 类机理路径（如静电 / 疏水分配 / π-π / 氢键 / 孔道限域 / 分子识别），无重复原型，给下游真实选择空间。
- **3**：覆盖尚可，但偏向单一策略，或含 1 对近重复。
- **1**：只返回一个显然原型，或多条实为同一原型的重复，无多样性。

### D3 身份纯净 / 无串库（Identity Purity）★ 一票否决项
每个返回原型的叙事/机制是否只属于其仿生身份。
- **5**：全部原型身份单一，叙事/机制主题与 ID 一致。
- **3**：个别原型有轻微主题漂移，但未误导主线。
- **1**：存在 chimera（混入他生物机制/叙事），或返回的机制张冠李戴。
- **规则**：任一返回原型 D3=1 → **本次闭环直接不通过**，不论其他维度多高。

### D4 机制归属可溯源（Attribution Traceability）
启发所依赖的定性机制/结构归属能否追到真实来源。
- **5**：核心机制归属均 ≥single_source 且在身份内，可点开看来源。
- **3**：多数可溯源，少量机制无明确归属但不影响主线。
- **1**：关键机制无来源、或来源是综述未追到原始论文、或疑似 LLM 编造。

### D5 设计启发的可操作性（Actionability）
设计提示是否具体到能播种一个真实设计，而非泛泛套话。
- **5**：提示含原型特异的可迁移要素（关键官能团/结构尺度/过程条件），下游能据此起方案。
- **3**：提示方向正确但偏笼统，需下游补很多。
- **1**：提示是无原型特异性的套话（如"增大比表面积""引入活性位点"），无信息量。

### D6 标注诚实度（Tagging Honesty）★
事实与线索是否清晰区分；推断是否标注。
- **5**：每条定量带 verification 等级；`llm_inference` 提示明确标注；每个候选都有 match_basis 与 direct_evidence 标记；无未标条目。
- **3**：多数已标，个别遗漏。
- **1**：未核实数据被当事实呈现，或推断提示/特征画像未标注、伪装成文献结论或 direct evidence。
- **规则**：D6=1 → **本次闭环直接不通过**（把未核实当事实是本库最危险的失效模式）。

### D7 边界 / 失效条件明确（Boundary Clarity）
是否说明该启发在什么工况适用 / 失效。
- **5**：给出 applicability（pH/温度/盐度等）与已知失效边界。
- **3**：有部分工况信息，边界不全。
- **1**：无任何适用边界，下游无法判断迁移风险。

### D8 下游可接手性（Hand-off Readiness）
输出结构是否完整到对抗设计模块能直接接手。
- **5**：字段结构完整，含 pollutant_profile、match_basis、verification/source_tier、honesty_ledger，下游可直接消费。
- **3**：结构基本可用，需少量人工整理。
- **1**：输出零散/缺字段，下游无法自动接手。

## 2. 通过判据（单次闭环）

一次闭环（一个查询 → 一组匹配 → 一份设计思路输出）判定为**通过**，需同时满足：

| 条件 | 阈值 |
|------|------|
| 一票否决项 | D3 ≥ 2 **且** D6 ≥ 2（任一 =1 直接不通过） |
| 核心维度 | D1、D3、D4、D6 每项 ≥ 4 |
| 其余维度 | D2、D5、D7、D8 每项 ≥ 3 |
| 加权总分 | ≥ 32 / 40（见下权重） |

**维度权重**（反映启发层定位，归属与诚实最重）：

```
总分 = D1×1.2 + D2×0.8 + D3×1.5 + D4×1.3 + D5×1.0 + D6×1.5 + D7×0.8 + D8×0.9
（满分按各维 5 分计 ≈ 49.5，按 ≥80% 即 ≥39.6 折算；为简化也可用未加权 ≥32/40）
```

未通过时，按下表回到对应整改步骤，**不在闭环测试里临时打补丁**：

| 失分维度 | 回到的整改动作 |
|----------|----------------|
| D3 | Path C 重清 chimera |
| D4 | Path A 补机制归属接地 |
| D6 | Path B/D 补分级标注 + 接口契约 |
| D1/D2 | feature-mapping 匹配/权重核对（Layer 2） |
| D5 | 设计提示重写（去套话、补原型特异要素） |
| D7 | applicability 聚合（Layer 1） |
| D8 | prototype.md 重渲 + 接口字段补齐 |

## 3. 测试协议（怎么跑）

1. **测试用例**：为每个金标准原型设计 **3–5 个查询**，每个查询含〔目标污染物 + 水质条件 + 工程约束〕。用例须覆盖：① 直接污染物证据命中的正例；② 依靠分子特征画像召回的正例（如 PFOA/SMX/BPA 一类新污染物）；③ 该原型**不应**被匹配中的负例（验证不乱推）。
2. **执行**：把查询喂给真实匹配链路（污染物标准化 → 分子特征画像 → direct evidence / feature-based retrieval → 输出原型 + 设计思路），记录输出。
3. **打分者**：由**独立于建库过程**的评审（第二个 agent 或人工）按本卡打分，建库者不自评。
4. **样本量**：每个金标准 ≥3 次闭环；5 个金标准合计 ≥15 次。
5. **金标准通过线**：单个金标准的全部闭环均通过，且负例**未被错误匹配**（不乱推也算质量）。
6. **关口**：**5 个金标准全部通过前，不扩到 100、不重建 pollutant_prototype_map、不把 design-rules 投入匹配层。** 第一个金标准通过先回报，确认方法可行再继续。

## 5. 与上游核查标准的衔接

本卡的 D3/D4/D6 直接依赖《分层核查标准》的 Path C / Path A / Path B+D 的执行结果。**先把那份标准的 P0 闸（chimera 清零 + 机制归属接地 + 性能分级 + 接口契约）跑过，再跑本卡**，否则 D3/D4/D6 必然不过，闭环测试只是重复发现已知问题。
