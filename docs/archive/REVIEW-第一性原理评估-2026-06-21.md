## 第一性原理诊断

### 1. 项目其实有两层，只建好了"诚实记账"层，"真知识"层基本是空的

去掉所有 honesty ledger / refuted log / guardrail 的包装，问一句：**库里到底沉淀了多少有证据的、可迁移的生物知识？**
答案是 510 条机制里 22 条有 verified/partial 证据，因果推理 96.7% 是 LLM 推断。抽查 mussel-foot-adhesion 的 mechanism[0]，causal_chain 是模板 `"基于机制: <机制名>"`，四个子字段 basis 全是 `llm_inferred`，boundary 是占位符 `"适用条件需根据具体机制验证"`——而且这条"第一机制"讲的是两性离子抗污 vs PEG，跟 mussel 对 ADRMATS 的真正价值（DOPA 黏附+金属螯合）无关。

所以建得最扎实的是**标签系统**：它非常诚实地告诉你"我大部分不知道"。这有价值（污染清理、去 chimera、去 refuted DOI 是真功夫、也必要），但要认清——**当前交付物的主体是"诚实地标注了空白"，不是"填上了空白"**。

### 2. 匹配器是 11 键静态查表，结构上无法保证"scope 正确的候选"，并且违反项目自己的契约

候选检索逻辑（`biomimetic_context.find_feature_based` + `feature_matching_rules.json`）= 把污染物拆成 token（芳香环/酚羟基/疏水性…）→ 查手工表 → 固定原型列表 + 手填权重。表里只有 11 个分子特征键。

后果（实测 BPA brief）：

- **chitosan** 作为 BPA 候选，挂出来的机制是"金属离子络合机制"（Hg²⁺/Pb²⁺/Cu²⁺），design_translation 写"捕获重金属离子"——**对 BPA 这个有机分子完全不适用**，纯靠"氢键"token 命中。
- **lotus-leaf** 作为 BPA 候选，机制 `基本原理: needs_review`，DT 写"油水分离膜"——**和溶解态 BPA 吸附无关**，纯靠"疏水性"token 命中。
- **polydopamine** 的 evidence_tier 标 `fact`，但那条 fact 是 CN114887602A 的**磷（P）吸附**专利，不是 BPA。

项目自己的 `adrmats-interface-contract.md` §4 明确要求 `applicability_fit` 和 `design_translation.idea` 必须 scope 正确。BPA brief 违反了它自己的标准，**却通过了全部验证器**。

这是结构性问题，不是可以 patch 的 bug：查表对"这个原型到底有什么证据、那个机制能不能迁移到这个污染物"没有任何表示。你可以逐个污染物手调表，但那是在维护答案，不是知识，且无法 scale 到 60–80 原型。

### 3. 绿灯验证器度量的是"结构完整 + 标签诚实"，不是"有用 + 正确"——仪表盘对 Yao 真正关心的问题是盲的

`check_brief_usefulness.py`（被 M7 当作"7/7 usefulness PASS"的证据）逐行读下来，只检查：字段是否存在、`candidate_honesty ∈ {fact,lead,inference}`、`material_handle`/`honesty_summary`/`boundary_summary` 是否非空字符串。**它不检查 scope 是否正确、fact 是否真、匹配是否合理。** 上面那个 0-fact、候选错配的 BPA brief，照样 PASS。

这是典型的 Goodhart：能测的代理指标都调绿了，但代理指标不覆盖目标。风险是——v0.2 "terminal delivery" 很可能在"验证器全绿"的底气上被宣布，而真正的可用性缺口（第 1、2 点）原封不动。

### 4. 流水线在以"自损-恢复"的方式空转，真瓶颈反而最没被自动化

246 commits 里大量是 revert/restore/rollback：`restore canon evidence stripped by 82fa2c0`、`rollback unsafe keyword-upgrade of 228 mechanisms`、`revert diatom-frustule.json corruption`、`revert unauthorized parking`、整个 R0–R1 "recovery" 里程碑是在一次 "office rewrite" 之后救数据。多 AI relay（Codex↔CC↔OpenClaw↔Cowork）本身是 churn 源——stale relay、outbox 未消费、错 reply_to、build 把数据洗掉，这些你在总览里也列了。

第一性原理：**当协调机制产生错误的速度 ≳ 它产生可验证知识的速度，再加编排轮次（M8–M11）不会收敛。** 真瓶颈是"把 PDF 变成有 locator 的 verified fact"这个体力活，而它恰恰最依赖人工、最被往后推（report 自己的 backlog：facts 卡在"need PDF access for quote extraction"）。一个月下来只攒了 17 条 from_source 因果卡、22 条 verified 机制，就是这个瓶颈的读数。

## 分域回答："能否达到预期效果"

- **重金属吸附（Pb/Cr/Cu…）：能，且接近能。** Pb(II) brief 的候选（mussel DOPA 螯合、fish-scale HAp→磷氯铅矿、chitosan 氨基配位、shells 离子交换）是真·scope 正确、有直接证据的好仿生匹配。这是项目天然的"赢面"子域。M8 把这些补上真实 quote，是能产出诚实可用 brief 的。
- **有机微污染物（BPA/PFOA/SMX/染料）+ 油水分离：当前方案达不到。** 0 facts、候选 scope 错配或全 inference。这不是多写 DT、多贴 quote 能补的——底层知识不在库里，且匹配器把错 scope 的候选拉进来。需要 (a) 库里没有的、针对性的文献，(b) 一个懂"机制→污染物迁移"的匹配器，而不是 token 重叠。

---

## 建议（按杠杆排序）

1. **把"结构检查"换成"结果检查"，并以它作为 v0.2 的门。** 建一个小 gold set（如 8–12 个污染物查询 + 专家判定的"正确候选 + 正确机制 scope"），brief 评分用：scope-正确候选的 precision、**误导性候选的 false-positive 率**、标 fact 的是否真 fact。不建这个，绿灯会一直遮住真缺口。

2. **从源头修匹配器的 scope 问题，或显式隔离它。** 要么给每个原型标注"它的证据实际覆盖哪些污染物类"，匹配器只在原型的**有证据机制**能迁移时才出候选；要么把纯 token 命中降级到一个明确分开的"发散/思辨"槽位，使其不可能被当成有据候选。BPA→chitosan 金属机制这种**绝不能**出现在正常候选位。

3. **把 v0.2 的范围收到知识所在的地方。** 认真考虑 v0.2 就交付"仿生重金属吸附"这个强核心、做到 terminal verified，并明确把有机物/油水分离标为"exploratory, inference-only"。这诚实、可达、不过度承诺。v1.0 扩到 60–80 应由"哪些污染物域缺证据"驱动，而不是再加一批同质的金属原型。

4. **砍掉制造 churn 的编排开销。** 既然真瓶颈是人工 PDF→quote，"一个写入者 + 禁止批量重写 canon + 直接做证据提取"大概率比再加编排轮次产出更多 verified fact。进度用"新增 verified facts 数"来计，不要用"完成 task/batch 数"来计。

5. **给 canon 瘦身。** 单个原型 55 条机制、全库 96.7% llm_inferred，是稀释信号的注水。把低信号的 llm_inferred 机制剪掉（或移到显式"假说"架）能让 verified 核心可读，也让 terminal 验证目标可达。

---

## 一句话给 Yao 的决策点

不是"项目卡住了"，而是"**完成的定义错了**"。现在的完成定义是"验证器绿 + 字段齐 + 标签诚实"；你要的完成定义是"**brief 能让一个材料工程师的决策变好、且不被误导**"。把后者写成一个可测的门，放在 M8 之前——否则 M8–M11 会很勤奋地把一个真实可用范围有限的库，包装成全绿交付。
