# 第一部分 · 诊断

## 1. 一句话结论

数据地基扎实，但组装出的 prototype.md 现阶段不能交给 ADRMATS 用，约 7 个原型的损坏是语义性的（错生物、错叙事），不是排版问题。损坏全在桥接、不在源数据，所以可恢复。以质量为先，重点不是打补丁修桥接，而是换架构（第 9 节）并加一组质量闸（第 10、11 节）。

## 2. 重要的好消息：编造问题已从源头解决

v2 提示词逐字采纳了证据完整性铁律，禁止用训练记忆补充，要求每条数据带页码锚点，并对 evidence 分级。重建后的 mussel 文件里出现 10 个真实 DOI，是真实提取。所以 315 个提取 JSON 是真实、有接地的资产，这是最难的一块。诚实声明：审查者无法直接对 315 个 JSON 重跑核对（被 gitignore），信心来自方法与抽查，不来自全量复核（见第 13 节）。

## 3. 产出质量深度核查（全部 42 个 prototype.md 实测）

### 3.1 结构与覆盖
- **0/42 有 YAML frontmatter。** 下游按结构化字段解析的 agent 直接读不了。
- **7 个占位符**（约 205-235 字节、各 6 个 `[待补充]`、零数据）：biomineralization-template、diatom-inspired-porous、dna-aptamer、iron-oxidizing-bacteria、plant-tannin、scallop-shell、silkworm-silk。
- **6 对完全重复**：alginate/alginate-adsorbent、chlorella/chlorella-cell-wall、metal-organic-framework/mof-adsorbent、starch-adsorbent/starch-granule、superhydrophobic-artificial/superhydrophobic-surface、wood-structure/wood-xylem。唯一原型约 36 个。
- **12 个内容单薄**（<3KB）。
- **verification=verified 全仓库 0 处。**
- **applicability 全为 null**、无 constraint 数据，Layer 1 无法工作。

### 3.2 最严重：原型身份被污染（语义 chimera）
约 7 个内容原型的 `organism_scientific` 列了 3-5 个互不相关的生物，叙事讲错的仿生策略：
- **mussel-foot-adhesion（贻贝足丝）**：organism 列成荷叶/贻贝/水稻/纳米比亚甲虫/猪笼草，叙事整段是超疏水油水分离，不是贻贝螯合，性能行逐字重复 8 行。
- **fish-scale-hydroxyapatite、water-strider-leg**：与 mussel 共用同一份错误五生物列表，叙事同为油水分离。
- **cactus-spine、pitcher-plant-slippery-surface、spider-silk**：共用"猪笼草/甲虫/仙人掌/蜘蛛丝"列表。
- **namib-beetle**：列成荷叶/鱼鳞/甲虫/Salvinia。
- **注意例外**：sulfate-reducing-bacteria 列多个是合理的 SRB 属，不算 chimera。

成因：桥接关键词路由过宽，把多主题综述同时路由到多个原型，`dict.update()` 合并叙事时互相覆盖。对 ADRMATS 的后果是检索返回语义错配的设计上下文，比空白更糟。

### 3.3 证据可追溯性
- **行级溯源弱。** 性能行大多写 `source=patent` 但无专利号，DOI 没绑到具体性能行。
- **数据自评但未核实。** `evidence=reliable` 是提取 LLM 自评，verification 仍 0。现状是"有接地、自评可靠、未独立核实"。

### 3.4 质量结论与可用部分
底层 JSON 好，prototype.md 现阶段不能交给 ADRMATS。约 7 个原型损坏是语义性的（需重建）。相对好的约 10-14 个（单生物、内容扎实）：alginate、chitosan、cellulose-nanocrystal、cell-membrane-ion-channel、diatom-frustule、lotus-leaf、magnetic-bacteria、metal-organic-framework、silk-fibroin、chlorella 等，但仍缺 frontmatter、verification、Layer 1 数据。

## 4. 与现有质量审计的关系
质量审计准确（3 个桥接 bug、6 对重复、无 frontmatter、校验 1.5/6、0 达标）。本文件补两点：3.2 的语义 chimera 比"主题偏离"严重得多；以及架构与 ADRMATS 视角。

## 5. 核心发现：价值被倒置了
315 个结构化 JSON 是核心资产（有接地、可查询、带 provenance）。桥接把它降级成有损 markdown（截断、`dict.update()` 覆盖叙事=3.2 chimera 成因、丢 source_file、ID 分裂、无 frontmatter），被降级的 markdown 反被当成库本体和 ADRMATS 接口。

## 6. ADRMATS 就绪性差距
- **Layer 1 条件预筛失效**：constraint_prototype_map 缺失、applicability 全 null，无法按 pH/温度/盐度筛。
- **Layer 2 加权匹配不接地**：权重手填、非从语料导出。
- **Layer 3 组合推理**：有损、无 frontmatter、约 7 个语义错配。
- **横切：verification 0%**，ADRMATS 不应把这些当事实。
结论：尚不能支撑 ADRMATS，缺口集中在五处（Layer 1 无数据、权重不接地、接口是 markdown、约 7 个语义错配、数据未核实）。

## 7. 匹配层是空的，不只是有 bug
条件预筛无数据源（Layer 1 死）、Layer 2 权重手填。两处都应从语料导出。

# 第二部分 · 修改方案（给本地 AI 逐条执行）

## 8. 项目最高准则（质量为上 · 一切修改都服从）

任何修改、任何取舍，先对照这七条。它们高于进度、高于数量、高于"看起来完成"：

1. **质量高于进度与数量。** 宁可 30 个真原型，不要 100 个掺假的。
2. **每条数值必须可溯源到一篇真实文献的具体位置**（DOI 或专利号或标准号 + 页/表）。溯源不到的，不进库。
3. **一个原型 = 一个仿生身份。** 一个原型目录只描述一种生物原型，不混入其他生物的叙事（同类多物种除外，如各种 SRB）。
4. **未经独立核查的数据标 unverified**，ADRMATS 不得当事实用。
5. **空白优于错配。** 没把握就留空，绝不编造、绝不张冠李戴。
6. **有引用不等于可信。** 任何"看起来合理但没核实"的内容，默认不可信。
7. **拿不准就停下问人，不要猜**（触发条件见第 12 节）。质量为上意味着"达标"永远让位于"真实"，绝不为凑达标而保留可疑数据。

## 9. 修复总路线 + 必须先定的架构（gating）

**先定一件事，再写代码：正典是结构化存储，还是 markdown。** 推荐默认：**结构化存储作正典**（理由见第 5 节，markdown 是有损投影）。把这个推荐摆给项目负责人确认；若确认，按下面 schema 执行；若负责人坚持 markdown 为正典，回报后再议（但仍需第 10、11 节的质量闸）。

**结构化存储 schema（推荐，逐字段照建）。** 每个原型一个 JSON 文件 `prototypes_db/<prototype-id>.json`：

```json
{
  "id": "mussel-foot-adhesion",
  "name_zh": "贻贝足丝",
  "name_en": "Mussel Foot Adhesion",

  "biomimetic_dimension": "分子仿生",
  "features": ["邻苯二酚配位", "湿态粘附"],
  "applicability": { "pH_range": [3, 9], "temp_range": null, "salinity": null },
  "performance_data": [
    {
      "pollutant": "Hg(II)", "material": "PDA@Fe3O4",
      "qmax": 318.47, "qmax_unit": "mg/g", "removal_rate": ">95%",
      "ph": 5.0, "temperature": 25,
      "source": "literature", "ref_doi": "10.xxxx/yyyy",
      "source_file": "组3/Zhang2016.pdf", "page": "6", "locator": "Table 2",
      "evidence_text": "原文一句话引用",
      "verification": "verified", "confidence": 0.9
    }
  ],
  "mechanisms": [
    { "name": "邻苯二酚-金属双齿配位", "description": "...",
      "functional_groups": "儿茶酚/胺基", "source": "literature",

    { "constraint": "物理涂层稳定性", "relevance": "high", "explanation": "..." }

```

**导出规则（从结构化存储自动生成，禁止手填）：**
- `feature-mapping.json` 的污染物→原型权重：由该原型对该污染物的证据强度决定，公式见第 11 节。
- 缺失的 `constraint_prototype_map`：从各原型的 `engineering_constraints` 按约束类型归集。
- `applicability`：从该原型各论文报道的测试工况聚合，无报道则 null（诚实留空）。
- `prototype.md`：从该 JSON 渲染成人类视图，带完整 YAML frontmatter，不再当事实来源。

## 10. 逐问题修复卡（按 P0 → P1 → P2 顺序做）

每张卡：**改法 / 验收 / 边界**。前序卡未过验收，不做下一张。

### P0-1 语义 chimera（最高优先）
- **改法**：重建受污染原型。归入某原型 X 的条件是该条 knowledge_item 的生物/材料**确实是 X**（看 JSON 的 `prototype_targets` 字段确认，而不是仅关键词命中）。叙事只能来自主题为 X 的论文；多篇时按论文分组保留为 list，**绝不 `dict.update()` 覆盖、绝不跨生物合并**。
- **受影响清单（优先重建）**：mussel-foot-adhesion、fish-scale-hydroxyapatite、water-strider-leg、cactus-spine、pitcher-plant-slippery-surface、spider-silk、namib-beetle。（sulfate-reducing-bacteria 不算。）
- **验收**：每个原型 organism 单一（或同类多物种），叙事主题与原型 ID 领域一致，跑第 11 节一致性校验通过。
- **边界**：某原型清洗后内容过少 → 标"低覆盖、待补文献"，不硬填、不借别的生物的内容凑数。

### P0-2 接口架构（gating）
- **改法**：执行第 9 节。负责人确认后按 schema 建结构化存储，markdown 由它渲染。
- **验收**：结构化记录建成，markdown 由它生成，二者一致。

### P0-3 六对重复
- **改法**：每对二选一为 canonical（**以 `feature-mapping.json` 的 `prototype_metadata` 里实际使用的 ID 为准**），把另一个内容合并进 canonical（去重），删非 canonical 目录，并修 `map_to_prototypes.py` 的回退映射 ID 使其等于 canonical（根治分裂）。先查 feature-mapping 确认哪个 ID 为准，再合并。
- **验收**：无重复目录；`map_to_prototypes.py` 不再产生分裂 ID。

### P0-4 verification 全 0（核查层）
- **改法**：实现核查流程。对每条 `source=literature` 的性能数据：① 解析 `ref_doi`（Crossref/web）；② 开对应 PDF/`source_file` 核对该数值确实出现、且对应同一材料与污染物；③ 三步全过 → `verification=verified`，否则标 `needs_review` 或删除。产出核查报告（真实 / 编造 / 无法核实 表）。
- **验收**：喂给标杆的论文先做，标杆性能数据 100% 经核查；不存在"verified 但 ref_doi 解析不到"。
- **边界**：新提取（直接读 PDF 产出）可直接 verified，但必须记 `ref_doi` + `source_file` + 页码。

### P0-5 行级溯源弱
- **改法**：每条性能/机制数据必须绑可解析的 `ref_doi` 或具体专利号/标准号到该行。`source=patent` 无号 → 回原 JSON 找号补上；找不到 → 标 `needs_review`，不得 verified。
- **验收**：不存在"已 verified 但无号/无 DOI"的条目。

### P1-1 Layer 1 无数据
- **改法**：从提取数据导出 `applicability` 与 `constraint_prototype_map`。applicability 从该原型各论文报道的测试 pH/温度/盐度聚合，无报道则 null。constraint_prototype_map 从 `engineering_constraints` 按约束类型归集原型。
- **验收**：有报道工况的原型 applicability 非 null；constraint_prototype_map 存在且非空。

### P1-2 Layer 2 权重手填
- **改法**：用第 11 节公式从语料导出权重，替掉手填值。
- **验收**：每个权重可追溯到证据（篇数/qmax/verified 比例），不再手拍。

### P1-3 无 frontmatter
- **改法**：渲染 markdown 时按 `templates/prototype-template.md` 输出 YAML frontmatter（id、name、category、organism、biomimetic_dimension、applicability、features）。
- **验收**：42/42 有 frontmatter 且字段齐全。

### P1-4 校验脚本补齐
- **改法**：补齐质量审计的 6 条规则 + 第 11 节的溯源/单生物/重复校验，接 pre-commit。
- **验收**：脚本能拦截断链、孤儿、缺 frontmatter、缺 ref、verified 无锚点、chimera、重复行。

### P2-1 七个占位符
- **改法**：补文献重提取；补不到 → 显式标"低覆盖、待补充"，不硬填、不编造。
- **验收**：占位符要么有真实内容，要么显式标低覆盖。

### P2-2 文件内重复行 / 静默截断
- **改法**：渲染前去重（同 pollutant+material+value 视为重复）；不静默截断，结构化存储里全保留，markdown 视图如需截断要标注并优先保留 verified + 高质量条目。
- **验收**：无文件内重复行；无无提示截断。

## 11. 数据判定规则（机械套用，不靠判断）

遇到下列情形按规则处理，不要凭感觉：

- **一条数据可标 `verified`** ⟺ `source∈{literature,patent,standard}` 且 ref 可解析（DOI 解析到 / 专利号或标准号确切）且该数值在该来源指定页/表确实出现、材料与污染物一致。三者缺一不可。
- **一条数据必须删除** ⟺ 来源查无此文，或数值在来源中找不到。
- **一条数据标 `needs_review`** ⟺ 有来源但缺页码、或引用过短、或数值精度不一致、或 `source=patent` 无号。
- **一个原型判为 chimera（需重建）** ⟺ organism 含 ≥2 个不同类生物 且 叙事主题与原型 ID 领域不符。（同类多物种如各种 SRB 不算。）
- **任何字段缺来源** ⟹ 留空，不编造填补。
- **Layer 2 权重公式**（可先用此式，后续再校准）：`weight = clip(0.4·norm(n_verified_papers) + 0.4·norm(max_qmax) + 0.2·verified_ratio, 0, 1)`，其中 norm 为对该污染物下所有原型的归一化；无 verified 数据的原型 weight 暂置 0 并标低置信。

## 12. 何时必须停下来问人（不要自行决定）

出现以下任一情况，停下、回报、等指示，不要猜：

- 接口架构（结构化存储 vs markdown）二选一拿不准。
- 某原型清洗后内容过少，不确定标低覆盖还是补文献。
- 某条数值在来源里找不到，但删了会让原型不达标。**这种情况一律删/降级，绝不为达标保留可疑数据**；若觉得为难，问人，不要自行放宽。
- 六对重复里 canonical ID 二选一与 feature-mapping 不一致或无法确定。
- 任何时候出现"为了让原型达标，想放宽核查标准或保留没核实的数据"的念头 → 立即停，问人。

## 13. 审查者的盲区（需本地 AI 先核实）
审查者未能访问 315 个 JSON（gitignore），"提取已接地"是基于方法、文件中真实 DOI 与抽查的高概率判断，不是全量复核。第 10 节 P0-4 的核查层正好覆盖：跑完就知道语料真实质量。在此之前把"提取扎实"当高概率假设、而非已证结论。

## 14. 给本地 AI 的执行起点

第一步做三件并行，做完一起回报，**接口决定之前不要大改桥接**：

1. 把第 9 节的接口架构问题摆给项目负责人定夺（推荐结构化存储为正典）。
2. 按 P0-4，挑喂给某一个标杆的几篇论文跑核查层（解析 DOI、开 PDF 核对数值），出"真实 / 编造 / 无法核实"报告。
3. 挑一个 chimera（如 mussel-foot-adhesion）确认其叙事确实跑偏到油水分离，复核第 3.2 节严重度。

回报后，按第 10 节 P0 → P1 → P2 顺序推进，每张卡对照其验收自检并回报，未过验收不做下一张。全程对照第 8 节七条准则；任何取舍以"真实"压过"达标"。遇第 12 节情形必停。
