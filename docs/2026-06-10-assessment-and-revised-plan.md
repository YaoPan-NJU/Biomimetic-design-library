# 通用仿生水处理设计参考库 — 第一性原理评估与修订推进计划

> 日期：2026-06-10
> 范围：对 `wastewater-treatment-universal` 分支（commit `792a81a`）的严格审阅，及收敛后的推进计划
> 评审依据：三份内部文档（project-sync / design-decisions / general-library-design）+ 分支实际内容 + 旧吸附库 `feature/extraction-results` 分支对照

---

## 1. 总体判断

架构作为"骨架"是合理的，选型（领域路由 + Markdown/JSON 双层 + 增量建设）成立。但须如实记录现状：**当前分支为纯骨架**——

- `prototypes/_index.json`：`total: 0`，原型池为空；
- 5 个 `entrypoints/*.json` 路由：全部为空映射（`[]` / `{}`）；
- 13 个 `domains/*` 目录：仅 `.gitkeep` 占位，无任何 `domain-profile.md` / `mapping.json`；
- `shared/cross-domain-links.json`：仅空骨架。

即：低复杂度部分（目录、模板、文档）已完成，高复杂度部分（可信、带参数、跨尺度的仿生内容）尚未触及。以下 7 点为第一性原理层面的风险，应在批量建设 13 个领域之前处置。

---

## 2. 七点第一性原理发现

### 发现 1：消费者与契约缺失（最关键）
旧库能够落地，是因为有清晰契约：`query(污染物, 水质, 约束) → BiomimeticDesignBrief`，输出供给下游材料设计 agent（ADRMATS），并有验收脚本保证契约成立。新设计将其替换为"由 LLM 直接读取 Markdown 与 JSON 路由并自行推理"，但**由谁查询、输入输出为何、如何判定检索正确**均未定义。参考库的架构由"如何被查询"反向决定；此项不定，则"是否合理可行"无法判断，亦无法测试。

**根因**：范围扩张将 1 个消费者隐含地变为约 4 个（材料/微生物设计、反应器/系统设计、提标改造、运行调控），各类的输入输出不同——不存在单一统一契约。

### 发现 2：范围扩张与已验证产能不匹配
旧库仅聚焦吸附一个方向、且配有专门的文献抽取与校验工具，最终仍为 **verified=0、evidence_level 多为 low、33 个原型中仅 13 个能产出 brief**。新计划将覆盖面扩大到约 13 个领域 × 4 个尺度，并将"四尺度设计启示"设为每个原型的必填项。**瓶颈不在架构，而在可信内容的产出速率。**

### 发现 3："四尺度必填"可能引入噪声
多数生物原型仅在 1–2 个尺度确有设计启示。强制填写四尺度，要么产生"暂无明确启示"占位，要么将低证据的推测表述为"设计参数"——即旧库 post-mortem 记录的 chimera（数据污染）问题。强制全覆盖与证据纪律相冲突。

### 发现 4："参数 + 仿真工具"既是最大价值点也是最大风险点
DD-006 承诺每个尺度给出"可直接输入 CFD/COMSOL/GPS-X 验证"的量化参数，这是差异化价值所在，但也是仿生学最薄弱处。判定门槛须为：**由仿生推导得来、相对常规工程具备非显然性、且可真正进入工具验证**的参数。若仅为教科书通用值（如 HRT 4–8h），相对设计手册无增量。

### 发现 5：运行调控入口可能为错位的范围蔓延
绝大多数运行调控属过程控制（ASM / 反馈控制）范畴，而非仿生范畴。"DO 偏低则增大曝气"很少是仿生问题。`operation-router` 的仿生着力点是否成立，需先行验证。

### 发现 6：旧库的工作机件被整体丢弃
孤立分支重建时清除了既有文件，并一并丢弃了 `biomimetic_context.py`（查询引擎）、经验证的 `feature-mapping.json`（四层映射）、`pollutant_profiles`，以及全部校验工具（一致性校验、chimera 检测、验收脚本）。新设计无打分 / 匹配逻辑、无校验脚本。将检索能力退化为"由 LLM 直接读取文件"，在精度与可测试性上构成倒退——除非此为知情的权衡取舍。

### 发现 7：两阶段路由尚未验证且当前全空
路由机制（入口 → 1–3 领域 → mapping.json 权重排序 → 跨域）合理但未经检验。在 0 原型条件下，无法判断权重、跨域链接、领域边界能否产生良好匹配。应先打通一条端到端纵切片，再横向复制。

## 3. 决策收敛记录（2026-06-10 讨论）

| 决策点 | 收敛结论 |
|--------|----------|
| 首个聚焦的消费者 | **反应器/系统设计**（新库相对旧库的真正增量，风险最高，最值得先行验证） |
| 样板工艺 | **A²/O**（污水厂最主流生化工艺，相关性最高） |
| 样板设计问题 | **进水波动下的分区自适应**（系统 / 抗冲击尺度；验证工具由 CFD 转为 ASM / 过程动态仿真） |
| 样板生物原型 | **微生物席 / 潮汐沉积物的氧化还原分层与昼夜锋面迁移**（含好氧颗粒 / 土壤团聚体作为"结构 / 并行"对照原型） |
| 架构修正（关键） | **独立厌氧池（锚定）+ 缺氧/好氧可移动锋面 + 机器人承担锋面观测与模型标定**，而非"统一池" |
| 物理边界（关键） | 厌氧无法按需快速生成（限速环节为硝酸盐反硝化，非溶解氧）；硝化菌生长缓慢、空间锚定；锋面迁移速度上限由最慢生物过程（硝化活性空间再分布）限定 |
| 组织主线 | **BNR 配置空间导航**：三轴 = 实现方式（空间 / 时间 / 结构）× 序列拓扑 × 回流路由；四条不变量界定可行域。命名工艺（AO/A²O/AAOA/Bardenpho/UCT/MUCT）是可行域内的点；自适应 = 运行时在该空间内移动 |
| 过渡带厚度连续谱（新增） | 引入 `front_sharpness`（过渡带厚度 / bulk DO 设定）作为连续控制变量，将"分立分区重配（空间）"与"SND / 微区共存（结构）"统一为一条轴，无需离散取舍。大气锋面（准静止锋 / 锋生锋消）作为动力学描述与可解释性表述，**明确为物理类比，不计入原型池** |

## 4. 修订推进计划：先验证后扩展（prove-then-scale）

### 第 0 步（立即）：先验证，再扩展
冻结"13 领域 × 4 尺度必填 × 5 入口"的同时建设，转为后续待办（backlog）。先完整跑通一条端到端纵切片（见配套文档《A2O-自适应缺氧切片-spec》）：1 个设计问题 + 1–2 个真实原型 + 一条路由 + ASM 验证情景 + 验收清单。**目标是证伪 / 证实"反应器/系统场景模式成立"这一命题本身。**

### 第 1 步：以切片回头校准设计规则
依据切片暴露的问题修订模板与路由 schema（如缺氧重配的参数字段、多入口去重规则）。

### 第 2 步：复制到 2–3 个相邻设计问题 / 原型，积累足以支撑一个完整领域的内容
确认产能足以支撑一个完整领域（建议 `shock-resistance` 或 `mass-transfer`），再考虑横向展开。

### 七点处置表

| 发现 | 处置 |
|------|------|
| 1 消费者 / 契约缺失 | 先固化**一个**消费者契约（反应器/系统），写入切片 spec；不追求万能契约 |
| 2 范围 vs 产能 | 先验证后扩展；13 领域转为后续待办 |
| 3 四尺度必填 | **松绑 DD-008**：改为"相关尺度必填、其余显式标注 N/A"，"思考每个尺度"降级为核对清单 |
| 4 参数门槛 | 写成**硬性验收**：每个参数须满足仿生溯源 + 非显然性 + 可进工具，否则不予收录 |
| 5 运行调控入口 | **暂缓** `operation-router`；待切片验证仿生在运行层是否有着力点 |
| 6 工作机件丢弃 | **恢复轻量证据纪律**：恢复 verified/unverified 字段 + 一个一致性校验脚本 + `engineering_constraints` 作为排除性约束；不重建原查询引擎 |
| 7 路由未验证 | 以切片的"单一设计问题命中 3 入口 × 3–4 领域"检验两阶段路由 |

## 5. 风险与开放问题

- **R1（高）**：A²O 自适应缺氧切片的核心参数（锋面迁移速度上限、缺氧重配响应时间、回流路由策略）目前均为"待文献 / 仿真标定"。切片成败取决于能否以文献 + ASM 动态仿真 + 机器人实测予以确证。此处正是旧库 verified=0 问题可能重现之处。
- **R2（中）**：自适应分区相对现有"摆动区 + 分段进水 + 可调回流"的增量，需在 ASM 动态情景中以量化方式证明（出水 TN/TP 方差、能耗），否则存在"为现有技术附加仿生标签"之嫌。
- **R3（中）**：连续流"可移动锋面" vs 好氧颗粒"结构 / 并行" vs SBR"时间相位"——三种实现方式何者最适于承载自适应、最易改造，尚无定论（实现方式轴尚未深入分析，已登记为后续待办）。（说明：过渡带厚度连续谱已将"空间 ↔ 结构"两支连为一条连续轴，见切片 spec §3.4 / §5；SBR 的"时间"支仍待并入。）
- **R4（低）**：机器人承担观测、曝气栅格承担执行，二者分辨率不匹配，且巡测存在采样滞后，需在控制设计中计入。

### 开放问题（留待后续讨论）
1. 配置空间是否升格为"反应器/系统"场景的正式组织主线（涉及总体设计重写）？
2. 四条不变量是否参数化为库的"配置合法性"校验规则？
3. 实现方式三分支（空间 / 时间 / 结构）是否各建立一个对照原型？
